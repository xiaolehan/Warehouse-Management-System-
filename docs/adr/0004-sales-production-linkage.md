# 销售单 ↔ 生产任务单显式关联与需求联动（D70）

> 状态：accepted（2026-09-10 会话 25 grilling 定案）

## 背景

公司是定制生产模式：销售下单后生产端才排产（出 BOM 或复用已有 BOM）。此前 `biz_sales` 与 `biz_production_order` **零关联**——客户问"货何时好"，销售只能挨个问生产/采购。阶段 20 需要打通这条链路（履约时间线见 CONTEXT.md「履约时间线」「预计可交付时间」词条）。

备选方案：
- **弱联动**：不建关联，按"成品"聚合在途生产单拼时间线——实现最简，但在途生产单不一定是为"这张销售单"排的，答复不准；
- **自动联动**：缺货销售单一建成就自动生成生产任务单——生产数量、批次、是否研发新 BOM 是生产的经营决策，系统越权代决风险高；
- **多对多关联表**：一张生产大单喂多张销售单、一张销售单拆多张生产单——需要"哪台货给哪张单"的分摊逻辑，当前业务体量用不上。

## 决策

1. **显式 1 对 1 关联**：`biz_production_order.sales_order_id` 可空。生产建任务单时**选填**关联的销售单（须同成品、正常且待出库）；一张生产单最多关联一张销售单，反向不限制（一张销售单可被分批生产覆盖）；通用备货单留空。多做的备货量不入关联。
2. **需求通知而非自动建单**：销售单创建时现货不足（含超卖，D69 建单已零库存校验）→ 站内信通知生产管理员"有销售需求待排产"（`biz_type=sales` 绑销售单，D21 范式，删除/作废/确认出库撤未读）。**系统不自动创建生产任务单**。
3. **履约闭环通知**：关联生产单入库且销售单仍正常待出库 → 站内信通知**建单销售本人**（精准到人，管理员不被轰炸；同样绑 `biz_type=sales`）。
4. **履约时间线**：销售单详情挂 8 节点时间线（下单/排产/物料准备/开工/装配 x/7/质检/入库/发货），数据全部复用现成事件（工序打卡、质检记录、采购行级预计到货 D61），不加新采集负担。
5. **预计可交付时间**：系统推算（缺料=max 补料行预计到货+工期；齐套/已开工=(开工|当前)+工期），**仅供参考非对客承诺**；生产可在任务单手工修正（`expected_completion_time`，@AuditLog 留痕），手工值优先于一切推算。工期挂在 `biz_bom.lead_days` 由生产建/编辑 BOM 时填写，**可空**——新品留空显示"待生产评估"，不设全局默认值（拍脑袋值会污染推算）。
6. **挂起待公司确认**（暂定行为已落地，不阻塞）：E1 库存竞争不预留不自动通知；E2 关联销售单作废不拦截、生产单关联保留（见 task_plan「待确认问题」）。

## Consequence

- 销售单与生产任务单之间有了第一条显式外键式关联（此前只有消息层面的模糊反馈，阶段 7 pick_list 失败通知）。
- 时间线的开工/入库节点时间为近似值（最早工序打卡/updateTime——任务单无独立开工/入库时间字段），若未来需要精确时间需补字段。
- 现货判断不预留库存（E1 暂定）：两张"现货充足"单先出库先赢，后者出库被硬校验拦截退回人工协调。
- 若将来业务需要"一生产单喂多销售单"，再引入关联表做分摊；当前 `sales_order_id` 单字段可平滑演进（关联表可迁移既有值）。
