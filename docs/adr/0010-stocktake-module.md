# ADR-0010: 盘点模块（快照留存 / 生效时点实时账面基准 / 无删除仅取消 / 盲盘导出回填闭环）

> 状态：accepted（2026-09-13，grilling 三轮定案，会话 32）

## 背景

客户需求文档 `wms_v1.docx` 痛点 4：「盘点耗时费力，循环盘点难以执行」；痛点 1「账实不符」亦以盘点为直接纠正手段。客户为 2000㎡ 平面库、人工计件（手数/称重）。系统是阶段 4（盘点/余料/成品追溯）中首个启动的子项——三子项全部出自客户文档，盘点痛点最直给、范式最成熟，故先行（余料/追溯后续再议）。

盘点模块有四个真正的分岔口，各有备选：

- **差异计算基准**：建单快照 vs 生效时点实时账面。快照基准直观（"建单时的账对建单后的实"），但盘点期间业务不冻结（冻结 2000㎡ 仓库全天作业不现实），期间发生的出入库已含在实盘数里，按快照调整会**重复调整**；
- **单据清理纪律**：盘点已调库存，"作废已完成单"意味着反向再动一次库存（多一条错账路径）；"删除"让审计敏感区的单据有"消失"路径；
- **审批层**：盘盈盘亏影响成本，要不要复用 BizApprovalOrder 加审批（对齐价格偏离 D29）；
- **录入效率**：「耗时费力」一半在逐行手敲——要不要做 xlsx 导入回填。

## 决策

1. **盘点单 = 仓储自选商品范围**（物料+成品，可全选即全盘），主从表 + 四态状态机：`盘点中(1)` → 提交 → `待审核(2)` → 审核生效 → `已完成(3)`；`已取消(4)`（1/2 可取消，零库存影响）；审核驳回退回 1 重录。建单时明细行快照商品名称/规格/材质/单位（对齐 D60/D63 范式）。
2. **盘点期间业务不冻结；差异 = 实盘数 − 生效时点实时账面**（非建单快照）。明细行记录三值：快照账面（展示/核对参考）/ 实盘数 / 生效时账面。快照时间页面显著提示。
3. **已完成终态不可作废；全模块无删除入口，只有取消**。盘错了的正确姿势是再盘一次纠正，审计链单向清晰。
4. **无跨部门审批层、无站内消息**：盘点是仓储内部账实校正；双人制衡靠「录入（仓储 admin+员工）≠ 审核（仓储 admin）」分工 + @AuditLog 留痕与操作日志快照（ADR-0009 基建）。明细不含金额列，财务成本影响走既有报表口径。
5. **允许部分提交**（≥1 行）：未录行标「未盘」不调整库存，其「上次盘点时间」不刷新，自然进入下轮待盘。「上次盘点时间」**查询派生**（最近审核生效行的生效时间），base_goods 不加列（无双写漂移）；建单勾选列表展示并按其排序（最久未盘排最前），支撑人工循环盘。自动排程留二期。
6. **盲盘导出 + xlsx 回填闭环**：导出盘点表默认不含账面数（盲盘防抄数，可切明盘）；导出表即回填模板，填好实盘列可导回批量回填（解析/错误行反馈范式照 BOM 导入），页面逐行录入双通道并存。录入页差异非零行标色；审核页顶部汇总（盘盈/盘亏/一致/未盘行数）。
7. **权限**：建单/审核/驳回/取消 = 仓储 admin；录入/**提交** = 仓储 admin+员工（D32 精神；**2026-09-13 修订**：初版提交也收口 admin，用户手测后指出不合理——员工实盘完应可直接送审，否则一切收口都绕回 admin；审核生效/驳回/取消仍收口 admin，「录入+提交 ≠ 审核」双人制衡不变）；只读 = 仓储全员 + 超管（D77 白名单/只读分组惯例）；库存调整走服务私有 increaseStock/decreaseStock（库存红线）。
8. **责任到行 + 全程操作人留痕（D85，2026-09-13 用户手测后追加）**：明细行建单时**逐行指定负责人**（每行必选，候选 = 仓储部门启用成员 admin+员工）；**员工仅可录入/导入本人负责的行，admin 可录任意行兜底**；盘点中 admin 可**改派**（人不在岗时调整）。行级盖**实际录入人 + 录入时间**章（页面录入与 xlsx 导入同样盖章，可能与负责人不同——如 admin 代录）；主单盖**提交人/取消人**章（建单人/审核人本就有）。负责人 = 计划上谁该盘，实际录入人 = 实际上谁盘的，两者分离才构成完整追溯。

## Consequence

- 并发业务下差异绝不重复调整（决策 2），代价是"快照数"只是参考而非基准——页面文案必须讲清三值含义，否则用户会困惑"快照 100、实盘 98，为什么只调 −1"（期间出库 1）。
- 无删除/无作废让盘点列表只增不减，靠状态筛选保持可读；审计视角任何盘点意图（含取消）全程留痕。
- 员工可录入+提交但不可审核/驳回/取消，仓储内部职责分离落地；若未来要按金额阈值加审批，BizApprovalOrder 框架现成（新 action + 审批人路由，对齐 D29）。
- D85 后员工被行级归属约束：代盘/替班必须经 admin 改派或 admin 代录，两者都会留下痕迹（改派发操作日志 + 行负责人变更；代录行录入人≠负责人）。**存量无负责人的历史明细行**（D85 前建的单）员工不可录、仅 admin 可录或改派后员工可录——语义自动落到"未指定"分支，无需数据迁移。
- 盲盘导出表即导入模板，格式零歧义；导入回填把「耗时费力」的录入环节压到最低。
- 「上次盘点时间」派生口径下，软删/取消单不影响统计（仅审核生效行参与）。
- 循环盘点的"自动排程"诉求被显式推迟到二期——若客户届时提出，需新建周期任务机制（当前无任何定时任务基建）。
