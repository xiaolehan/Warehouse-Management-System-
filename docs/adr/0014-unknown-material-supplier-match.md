# 未知物料供应商匹配（仓储人工触发，备注斜杠约定）

> 状态：accepted（D109；未知物料从"永远挂系统默认供应商"到"采购建档后由仓储一键回绑"）

## 背景

生产补料「未知物料」由系统自动建档（D60/ADR-0002），建档时统一挂 **系统默认供应商（id=1，D100 保护的锚点主数据）**，进价留空。原设计没有任何后续手段把它改绑到真实供应商——要么仓储手工逐单编辑，要么永远挂着"系统默认供应商"，采购、库存口径长期失真。

用户指定的业务流程（原话要点）：

1. 采购在采购申请明细的**到货备注**里按 `供应商名字/其他信息` 的格式录入供应商名字；
2. 系统匹配时**只读第一个斜杠之前**的文本（"其他信息"供采购自行记录发货方式等，不参与匹配）；
3. 备注之后，采购仍需**手动在供应商管理建档**（主数据质量由采购负责，系统不因一行备注自动造供应商）；
4. 上述两步完成后，由**仓储模块**完成未知物料与供应商的匹配回写。

## 决策

1. **信息载体既有字段**：复用采购申请明细 `arrival_remark`（D61 到货备注），不新增字段、不新增页面。前端在录入框 placeholder、列表头问号 tooltip、认领/修改到货计划弹窗表格下方常驻说明三处明示「供应商名字/其他信息，斜杠前须与建档全名完全一致」。
2. **名称解析规则**：先规整空白（trim + 前导/内嵌的全角空格 U+3000、NBSP U+00A0 折成普通空格——MySQL utf8mb4_unicode_ci 的 PAD SPACE 只豁免结尾空白，前导隐形空格会让精确匹配静默落空），第一个 `/`（兼容全角 `／`）之前的文本再 trim：
   - 无斜杠 → 整串作为供应商名（兼容旧 D61 自由文本，但查无此名时报错会提示"确认是建档全名而非简称/物流用语"，避免引导建出垃圾供应商）；
   - 多个斜杠 → 第一段（`华强电子/顺丰/到付` → `华强电子`）；
   - 斜杠前为空（`/顺丰`）→ 报错拒绝，原文案与来源单号一起回显让采购改正。
3. **数据源=最新一张采购申请上的备注明细**：仓储触发时，取该物料 `goods_id` 全部到货备注非空的申请明细，按**所属申请单建单时间（id 兜底）倒序、同单按明细 id 倒序**选一条。注意备注是在明细行上就地 update 的、不更新任何时间戳，因此"最新"锚定申请单建单时间而非备注修改时间——旧单上的事后修正不会跑赢新单；VO 与审计 detail 都带 `sourceRequestNo`，操作者和日志都能查知取自哪张单。申请单已逻辑删除的明细跳过（一张都没有按"无备注"处理）。
4. **人工触发，无后台扫描**：仓储在物料管理页对仍挂系统默认供应商（supplier_id=1）的物料行点「匹配供应商」。系统**不做**定时/到货自动扫描——建档与备注录入是跨部门的两步，自动扫描会在采购尚未建档时批量失败、产生噪音；人工触发时失败原因可以即时反馈给操作者。
5. **精确匹配 + 显式失败，可无限重试**：按供应商全名精确匹配（未逻辑删除行）：
   - 找不到 → 「查无此名，请确认斜杠前是建档全名（简称/物流说明请改备注）；采购可建档后重试」，**不改写**；
   - 多家同名（主数据异常，正常有应用层唯一校验拦截）→ 报错提示联系超管核对，不猜一家；
   - 解析出的名字恰好是占位主数据「系统默认供应商」(id=1) → 显式拒绝（否则条件更新 1→1 假成功，按钮永不消失）；
   - 物料已绑非默认供应商 → 拒绝（按钮在列表上也只对 supplier_id=1 的物料出现）；
   - 仅物料（type=material）可匹配，成品不参与。
   - 每条失败文案都附**仓储兜底出路**：「也可由仓储直接在物料管理编辑该物料绑定供应商」——单据进入待入库/已入库终态后采购侧无法再改备注，不能给死胡同指引。
6. **回写并发安全**：`UPDATE base_goods SET supplier_id=? WHERE id=? AND supplier_id=1` 条件更新，rows≠1 报"已被他人更新，请刷新"。
7. **权限**：仅**仓储管理员**触发（用户指定的责任部门；超管遵循 ADR-0009 业务只读，不放行）。
8. **留痕**：端点挂 `@AuditLog(module=物料管理, action=匹配供应商)`（切面全局语义为 `@AfterReturning`，**仅成功落审计**），detail 定格物料、匹配到的供应商名、来源申请单号与备注原文；失败原因即时返回操作者、不落审计（与全站其他业务动作口径一致，不为本端点改全局切面）；匹配成功无站内信（仓储本人即时操作，非跨部门待办）。

## Consequence

- 未知物料的供应商回绑依赖**采购按约定填备注 + 手动建档**两个前置动作；仓储触发时的报错文案承担了跨部门动作指引（找谁、做什么）。
- 匹配只回写 `supplier_id`，不动进价；进价仍由采购后续进货/采购申请链路维护（D101）。
- 历史未知物料（D109 之前建档、没有任何到货备注的）匹配按钮可见但触发会提示"未找到采购到货备注"——需要采购在该物料的采购申请明细上补一次到货计划备注（仅待采购/采购中单据可补），或由仓储直接编辑物料绑定供应商。
- 无 DDL、无后台任务；新增 1 个端点 + 1 个列表行按钮 + 1 个 VO；审计日志可追溯每一次**成功**匹配（含来源单号与备注原文）。
