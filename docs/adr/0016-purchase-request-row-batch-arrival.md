# 采购申请按行分批到货（行级到货状态 + 部分入库 + 每批一张多行进货单）

> 状态：accepted（D120，2026-09-20 grilling；用户手测第 7 题。配套 ADR-0015 进货单头行结构）

## 背景

原流程：采购认领后整单一次性「到货提交」（`status: 2 采购中 → 5 待入库确认`），不允许再次提交；只有撤回到货/驳回入库回到 2 后**整单重提**。用户场景：一张申请 20 个物料，19 个 9-23 到、1 个 9-25 到——原系统只能等 25 号全部到齐才能提交，先到的物料无法提前进入入库流程。

## 决策

1. **分批粒度=明细行，行内数量不可拆**（用户拍板，二选一中选简单口径）：一次「到货提交」勾选本次实际到货的行，每行按**申请数量整行到货**（数量字段在到货弹窗对勾选行只读展示=申请量，不支持「订 20 先到 10」）；行内数量分批明确不做。用户原例若指「同一种物料 19+1」则仍需等齐，系统用文案明示该口径。
2. **明细行加接收状态**：`biz_purchase_request_detail` 加 `receive_status`（1 待到货 / 2 本批待入库确认 / 3 已入库），同批一起提交的行用**批次标识**关联（新增 `arrive_batch_no` 或等价分组列；驳回/撤回按批次操作）。每行仍在认领时带预计到货时间（D61）与到货备注（D109），单价到货时按行填写。
3. **申请单头状态机扩展**：
   - 2 采购中 → 勾选部分行提交到货 → **5 待入库确认**（本批待确认；未到行仍 1）；
   - 仓储确认入库：本批行 2→3，合并生成**一张多行进货单**（ADR-0015）；若仍有行未入库 → 头状态回到 **2′ 部分入库·可继续到货**（前端状态文案「部分入库」，仍可被采购勾选剩余行再次到货提交）；全部行 =3 → 头 3 已入库；
   - 仓储驳回到货 / 采购撤回到货：只作用于**本批**，本批行回到 1、批次结束，已入库历史批次不受影响（纠正历史批次走进货单作废）。
4. **消息按 D21 绑定批次**：到货提交通知仓储仍发一条（文案带本批行数），`biz_type=purchase_request`、`biz_id=申请单 id`（不按批次拆 biz）；驳回/撤回撤未读沿用 `revokeUnreadByBiz` 语义，按批次标题白名单避免误撤他批待办（对标 D103 模式）。
5. **认领与到货计划不变**：认领仍对全部行填预计到货时间/备注（D115 起备注支持统一填充）；入库前可改行计划，不影响已入库行。
6. **生产补料幂等守卫不动**（D86：同一生产单至多一张在途补料单）——「在途」口径含部分入库态：全部行入库后才允许为该生产单再发补料。
7. **前端**：到货提交弹窗改为「勾选行 + 逐行单价」（勾选行的数量、物料只读；支持全选未到货行）；申请详情增加各行到货状态列与批次分组展示；仓储待入库列表展示本批行。

## Consequence

- 不同物料分日期到货不再互相阻塞；同物料数量分批仍不支持（用户已明确取舍，换取无行内数量累计/超交校验的简单模型）。
- 一次申请对应 0..N 张进货单（每批确认入库一张多行单），单号数 ≈ 实际到货批次，与业务感知一致。
- D104 采购申请时间线的「到货/入库」节点从单节点变为**按批重复节点**（第 1 批到货→入库、第 2 批……），DocumentTimeline 合成服务需支持批次数组。
- 已入库行不允许再改：纠正走进货单作废（整单作废会连同批其他行一起回冲——v1 接受该粗粒度，与 ADR-0015 整单作废决策一致）。
