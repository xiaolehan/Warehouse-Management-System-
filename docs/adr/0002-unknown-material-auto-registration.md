# 未知物料补料自动建档（修订 ADR-0001 决策 2）

> 状态：accepted（修订 [0001-production-picking-warehouse-boundary.md](0001-production-picking-warehouse-boundary.md) 决策 2 在未知物料行上的适用）

## 背景

ADR-0001 决策 2 要求：方案先行 BOM 行（`goods_id` 空）的物料选择移到"生产提交补料时"，**全部缺料行选齐才允许提交**。产品方指出：从未在仓库出现过的物料（未知物料）不应从已建档物料下拉里"就近选一个"——那是张冠李戴；首次出现的物料需要带着完整信息（名称/规格/材质/备注）进入采购链路，方便采购直接采购。

备选方案：
- 临时物料自由文本 + 入库时由仓储"转正"定料——即 ADR-0001 明确废除的 D59-Draft 残留机制，采购/入库两环节都要特判，走回头路；
- 引导生产先去物料管理建档再回来选——两步走，且把仓储拉回定料环节。

## 决策

1. **行级匹配四态**：齐套 / 部分缺料（已绑定、0＜库存＜需求）/ 严重缺料（已绑定、库存为 0）/ **未知物料**（行未绑定物料；绑定过的物料被软删视同未知）。未知物料同样阻断开工，单据级齐套状态枚举（ok/partial/block）不变。
2. **未知物料行补料＝内联信息 + 提交时自动建档**：该行不出现物料下拉；生产核对自 BOM 预填的名称/规格/材质/备注/单位并填申请数量，提交补料时系统自动在 `base_goods` 建档（`type=物料`，挂缺省供应商、进价留空由采购维护，规格/材质一并写入主数据（见 [0003](0003-material-spec-in-master-data.md)），照 D41 成品建档先例），回绑 BOM 行；此后采购/入库/价格回写全链路复用既有逻辑。
3. **入口权限**：生产管理员（与补料按钮一致）；不放开物料管理页的写权限。
4. **快照与分组**：补料生成的采购申请明细在提交时快照 BOM 行的规格/材质/备注并带「新物料」标记；同一张申请单内按【已有物料缺口】（部分缺料+严重缺料合并）与【未知物料（新物料）】两组展示。
5. **清理残留**：移除 ADR-0001-Draft 时代遗留的"采购申请明细 `goods_id` 可空 + 仓储确认入库回挂 BOM 明细"机制——自动建档后不再产生 NULL 物料行。

## Consequence

- `base_goods` 记录来源由两种变三种：商品资料手工建、BOM 成品建档、生产补料自动建档。
- ADR-0001 决策 2 的"全部缺料行选齐才允许提交"改为：已有物料行保持绑定提交；未知物料行走内联建档。
- 采购申请明细需承载规格/材质/备注快照字段与「新物料」标记，采购申请单详情页按两组分区展示。
- 齐套明细三处展示（下达弹窗/任务详情/补料弹窗）需带出规格/材质/备注列。
