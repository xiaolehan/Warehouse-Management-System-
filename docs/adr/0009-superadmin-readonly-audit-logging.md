# ADR-0009: 超管「真只读」与审计日志强化（可读性 / 手动删除 / 永久保留）

> 状态：accepted（2026-09-13，grilling 三轮定案）

## 背景

公司要求超管能看清每个人的操作（审计治理视角）。现状三个缺口：① 超管前端白名单只开系统页面，看不到任何业务单据页（后端读接口本就经 or-superadmin 模式放行）；② 后端部分业务写接口放行超管（如 `GoodsService.update` 超管走仓储分支可编辑商品资料），"审计角色"名不副实；③ 操作日志 `targetId` 从方法参数"猜"、`before_data`/`after_data` 从未赋值、`requestUri` 原始直出，看不懂"这次操作到底干了什么"。

备选方案：
- **仅前端只读**（按钮隐藏、后端不动）：超管账号直接调 API 仍可写业务数据，"只读"是表面功夫；
- **后端同步收紧为真只读**：审计角色不碰业务数据，语义干净，代价是要清点并收回既有超管写权；
- **异常操作实时告警**（库存/价格阈值 + 敏感操作推送）：本轮明确挂起，不混入本期范围。

## 决策

1. **超管 = 治理/审计角色，业务数据真只读**：前端白名单 + 菜单放开全部业务模块页面（操作按钮对超管隐藏）；后端业务写接口统一拒绝超管（含收回 `GoodsService.update` 超管编辑权）。保留写权仅：用户管理 / 公告 / 系统参数 / 安全策略 / 价格偏离审批 / 作废审批 / 部门审批。
2. **财务两模块（利润分析 / 年度经营统计）维持显式排除超管**——成本利润仅财务部门管理员可见，超管也不例外。
3. **操作日志写入时生成「操作描述」人话摘要落库定格**（从方法参数提取单据号/品名/数量），`before_data`/`after_data` 开始真正赋值（关键字段变更前后快照）；不做前端 requestUri 映射翻译（路由一改即失效且无数据快照）。历史记录无描述，前端兜底显示「模块+动作」。
4. **日志保留策略：永久保留、无自动清理**；超管可手动删除（操作日志 + 登录日志，物理删除），删除动作本身写一条操作日志留痕（谁删了哪张表多少条）。
5. **操作日志 xlsx 导出**跟随页面筛选条件，仅超管；登录日志不导出。
6. **异常操作提醒整项挂起**（曾讨论的阈值草案：单次库存变动 >500、价格偏离 ±30%，一并作废，恢复时重新定议）。

## Consequence

- 超管账号被盗的爆炸半径收窄：能看不能改业务数据。
- 超管在物料/成品页可见进价/售价列（与后端 `showPrice` 含超管的现状一致，前端首次可达）。
- 超管自身的治理操作（审批 / 删日志等）同样进操作日志，审计闭环。
- 收回写权后，原有"超管代管"习惯操作（如改商品资料）改由对应部门管理员执行。
- 手动删除为物理删除，删后不可恢复——这是该功能的目的本身；定期瘦身靠手动按条件清理，不建定时任务。
