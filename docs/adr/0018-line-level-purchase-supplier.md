# 进货单供应商行级化（明细行承载供应商，头级降为手动单统一填充口径）

> 状态：accepted（D131，2026-09-22 grilling；第三轮手测问题 4。修订 ADR-0015 的头行结构与 D123 的最新供应商口径）

## 背景

D123 给进货单加了**头级**供应商（手动建单必填），物料「最新供应商」取最近一张已入库正常单的头级值。但采购申请渠道的进货单是确认入库时由系统生成的（`createInternal`），**从不填头级**——D123 的 SQL 干脆把头级为空的单排除在最新性计算之外。结果是用户实测发现：走申请链换供应商进货后，物料「最新供应商」纹丝不动，永远显示绑定供应商+「默认」tag（进货 85/86 头级 supplier_id=NULL 实证）。

更深一层是结构矛盾：申请 35 的两行物料分别来自胖牛、胖乐两家供应商——**采购申请天然按物料行混供应商**（需求驱动，不是供应商驱动），而头级单字段一单只能挂一家。当时 `createInternal` 留空不是遗漏，是模型装不下。

候选方案：A 行级供应商 / B 按供应商拆单（一供应商一张进货单）/ C 头级取多数供应商。

## 决策

1. **供应商落明细行**：`biz_purchase_detail.supplier_id` 为权威；申请链路的供应商在**到货提交**时逐行选择（预填物料绑定供应商、可改），确认入库生成进货单时按行复制。头级字段保留：手动建单仍走头级下拉、统一填入所有行（一单一供应商，交互不变）；内部生成单头级留空，不做派生。
2. **最新供应商口径改行级回退链**：最近一张「记录了供应商」（`COALESCE(d.supplier_id, p.supplier_id)` 非空）的已入库正常进货单 → 行级空回退头级（存量单）→ 再回退绑定供应商标「默认」。
3. **否决拆单（B）**：按供应商把一批拆成 N 张进货单虽然贴近真实采购，但会连锁改写 D120 刚落地的「每批一张进货单」语义、按批消息撤销、时间线节点——代价大于收益。也否决 C（头级取多数）：申请 35 的两行必错一边，信息有损正是本次要修的病。
4. **到货备注退回本位**：供应商的结构化承载移到「供应商」列；到货备注保持 D109 首次匹配线索与物流/分批等自由信息用途，不做备注文本解析（脆、且与结构化字段双轨漂移）。
5. **存量不追溯**：历史头级为空的单不回填（演示数据 85/86 一次性人工修正除外）；其「最新供应商」继续走回退链显示。

## Consequence

- ADR-0015 头行结构修订：明细行从「物料×数量×单价」扩展为「物料×数量×单价×供应商」；同一物料一单一行的唯一键不受影响。
- D123 的「头级必填」收窄为「手动路径必填」；CONTEXT.md「进货单」「最新供应商」「到货备注」词条同步修订。
- 一张进货单可以合法地混合多供应商（内部链路）；列表头级列对内部单显示「—」，行级真相在详情。
- 进货退货的供应商展示随来源明细行走（行空回退头级）。
- 换供应商场景闭环：申请→到货（选新供应商）→入库→物料「最新供应商」如实更新，无需仓储再手动干预。
