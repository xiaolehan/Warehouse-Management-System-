# ADR-0005: 生产任务单「手动终止」区别于「作废」，终止联动退料

> 状态：accepted（2026-09-10 会话 26, D73）

## 背景

销售单取消后，进行中的生产任务单需要一个业务上"做了一半不做了"的终态，并保证已领物料回到库存，避免库存错误。阶段 20 挂起的 E2（关联单作废）经确认：销售取消不直接越权终止生产，而是发消息由生产管理员判断是否手动终止。

现有终态（D40/D42）：
- 4=已完成（正常完工入库）
- 5=已作废（单据不该存在）
- 6=已报废（质检不合格不可修复）

缺少"做了一半不做了"的语义——作废=单据不该存在，会清空步骤实例展示；报废=质检不合格。两者都不对。

备选方案：
- **复用「作废」**：语义混淆（作废=单据不该存在，且会清空步骤展示）；
- **销售直接终止生产单**：越权——生产现场状态、物料是否能退、是否要改做其他单，只有生产管理员能判断；
- **新增「已终止」状态 + 退料联动**：语义独立，权限归生产管理员，终止即生成退料单回流入库。

## 决策

1. **新增状态 7=已终止**（1/2/3 可进入，不可逆，仅生产管理员，原因必填，@AuditLog）。语义区别于作废（5=单据不该存在）与报废（6=质检不合格）。
2. **终止与退料单生成一个事务**（`ProductionPickService.terminate`），退料量以「已领未退净额」（PICK+SUPPLY 已发料 − RETURN 已发料）为上界服务端兜底，防多退虚增库存。
3. **已有进行中退料单时跳过自动生成**（防堆叠口径与 `createReturn` 一致），前端提示人工核对。
4. **已终止单不参与 UNFINISHED_STATUSES**（D66 BOM 保护、现货/缺料推算不受影响）；打卡/质检冻结但记录保留可见。
5. **销售取消通知绑 `biz_type=production_order`**，生产单任一终态（完成/作废/报废/终止）撤未读，对齐 D21 范式。

## Consequence

- 状态机扩展需扫荡所有 statusText/状态闸（本阶段已覆盖打卡/质检/时间线/前端 tag）；后续新增终态判断默认不含 7。
- 终止 = 业务终态，不回滚；需要恢复只能新建生产任务单。
- 退料单由终止自动生成但仍走仓储确认出库（回流），保持仓储枢纽角色不变。
