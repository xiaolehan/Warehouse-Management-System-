# 销售订单终止：独立于作废/删除的第三条取消通道

客户取消订单是正常业务闭环，而现有两条取消通道语义都不合身：**删除**（当天建错当天擦，逻辑删除、无痕）与**作废**（单据纠错，"不该存在"，需仓储 admin 审批执行）。新增**行级终止**第三通道：语义 = 客户通知后的正常取消，**免审批立即生效**，落在 `biz_sales_detail` 明细行上（一单多成品可只终止部分行），全部行终止时订单头自动置 `biz_status=4 已终止`（派生终态，部分终止时订单仍正常）。仅限未确认出库的有效单——已出库的取消一律走销售退货（实物回流）或作废（开错单）。

为何不复用作废：① 作废是整单粒度且需审批，与"客户取消、立即生效"相反；② 两者都要在统计上与"开错单"可分辨；③ 终止是业务动作（客户真的取消了），作废是纠错动作（单据本不该存在）。

关键取舍（Q20a）：销售终止**不越权自动终止**关联生产任务单——生产终止需要人工判断逐行退料数量与差异备注（废料/损耗必填原因），系统无法替人填。落地为"通知生产管理员 + 冻结关联任务的资源消耗动作（领料/补料/开工/完工/质检/打卡/成品入库申请及确认；放行退料、终止任务、查看）→ 生产管理员在既有手动终止流程（ADR-0005）点终止完成闭环 → 回执建单销售本人"。

## 会话 58 修订：触发源扩展为三条取消通道同口径 + 采购侧半闸门

落地实测发现两个口径缺口，本 ADR 扩展如下（冻结语义不变，触发源与下游口径收紧）：

1. **触发源扩展**：原冻结只认「明细行 terminate_status=2」。实际生产任务单还会因销售单**整单删除**（D73 通道）或**作废**（D73 通道）失去需求来源，原先这两种情况不冻结——生产仍可开工/补料，与行终止口径不一致。现统一：`SalesTerminateGuard.freezeInfo` = 行终止 ∨ 销售单已删除 ∨ 销售单已作废（∨ 已冲抵），三条通道一视同仁。
2. **采购侧半闸门**：原设计未覆盖「生产补料 → 采购申请」这最后一环。现冻结采购**发起类**动作（认领 process、到货提交 arrive），放行**收尾类**动作（确认入库 confirmReceive、到货撤销/驳回、驳回申请单、删除）——理由：已提交的到货批次是已花成本，必须能收尾入库，否则在途单悬挂；而未发起的采购不应在需求已取消后继续花钱。
3. **一键撤销出口**：被冻结的在途补料申请（status 1/2）原先只能由申请人本人在采购页逐单撤销；生产终止弹窗现提供「一并撤销在途补料采购申请」勾选（`revoke-by-production-order` 端点，权限=申请人本人或生产管理员，前置=任务单已冻结，撤消息 + 通知采购管理员）。
4. **显性化**：任务单列表/详情、采购申请列表、成品入库页透出 `salesFrozen` 标志与原因（行终止附终止留痕），受冻结的操作按钮置灰——冻结不能只靠报错后才被用户发现。
5. 修复列表「关联销售单」列把 biz_status=4（已终止）误标为「已作废」的文案 bug（现在 2=已作废 / 3=已冲抵 / 4=已终止 分辨显示）。
