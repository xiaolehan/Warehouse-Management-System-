# 物料规格/材质入主数据，唯一性改按「名称+规格」

> 状态：accepted（扩充 [0002-unknown-material-auto-registration.md](0002-unknown-material-auto-registration.md) 的建档内容；修订 CLAUDE.md 旧约束「每种商品一条，名称唯一」）

## 背景

产品方给出领域事实：公司 BOM 中存在**同名物料、不同规格**。库存按物料记录管理，两种规格必然是两条记录；但原应用层校验强制 `goods_name` 全局唯一（`GoodsService.checkGoodsNameUnique`），同名物料只能把规格塞进名称（如"轴承M8"）或挤在一条记录里，下拉/列表只显示名称导致选错。规格/材质原本只存在于 BOM 明细（`biz_bom_detail`），主数据无对应字段。

## 决策

1. `base_goods` 新增 `spec`（规格）、`material`（材质）字段；备注沿用既有 `description`。物料管理页列表与表单展示并可编辑，维护权限沿用主数据现状（仓储 admin 全字段；采购仅进价）。
2. **唯一性：`type=material` 按 名称+规格 唯一**（应用层校验替换原名称唯一）；同名不同规格各自成条。`type=product` 保持名称唯一，BOM 成品建档逻辑不变。
3. BOM 明细的 规格/材质 字段保留，语义为「该成品对该物料的要求快照」；BOM 编辑选中物料时自动预填主数据值（可改）；未知物料自动建档时把行上的值写入主数据。
4. 补料/采购链路向采购展示的规格/材质取申请单明细上的快照；所有物料下拉选项文案升级为「名称（规格/材质）（单位）」防混选。

## Consequence

- `GoodsService.create/update` 校验、物料管理页与表单、`GoodsOptionVO` 及各下拉调用点需同步修改。
- 历史数据不迁移：`spec` 可空；原规则下不存在同名记录，放宽后无需合并数据。
- 展示与消息中出现物料的地方（齐套表格、补料弹窗、采购申请详情、齐套预警消息的缺口明细）统一带规格，避免同名歧义。
