# 销售端内嵌「+新品」快速建品（商品建档触发方扩展为销售动作）

> 状态：accepted（D121，2026-09-21 grilling；第二轮手测问题 1。修订 ADR-0003/0004 的主数据边界）

## 背景

「商品资料管理=主数据」铁律下，成品此前只能由人工在基础资料端建档（销售对主数据只有定价权，无建档权——见 CONTEXT.md 标准售价词条）。D112 落地后销售卖资料里不存在的成品时，链路是：下单（行标「零库存·无BOM」）→ 生产管理员收缺货消息 → 人工建档+建BOM → 批量下达。但用户实测发现一个死头：**卖的是「资料里根本不存在的全新成品」，销售连销售单都写不出来**——成品下拉搜不到该商品，无法选行，后面整条联动无从触发。上一轮定的「先建档后下单」单向引导被推翻：建档这一步本身卡死了销售。

## 决策

1. **商品仍由系统建档，主数据「人工建档」的边界放宽为「销售建单动作可触发建档」**：SalesView 成品下拉旁内嵌「+ 新品」小表单（名称/规格/单位/售价四项），提交走新端点 `POST /base/goods/quick-product`，由系统按主数据规范自动建档。建档权不交给销售手工编辑界面——销售能**创建**成品，但仍不能改档、不能建物料。
2. **快速建品字段强制收窄**：仅四项入参；`type=product`、库存 0、无进价、正常状态、无 BOM 全部服务端强制，销售不可注入。规格选填（成品仍名称唯一，同规格冲突走同一条路）。
3. **同名冲突不报错、直接选用**：成品名唯一铁律不变；已存在同名成品时端点返回已有商品并带 `existing=true`，前端提示「已存在同名成品，已为你选用」。避免「先搜后建」的重复建档路径。
4. **权限镜像销售建单守卫**：销售部门成员（admin+employee）可调；仓储/采购/生产管理员拒；超管按既有业务写铁律保持只读（不写主数据）。
5. **后续链路零新建设**：建出的成品立即自动选中进当前行，行上自然出现 D112「零库存」「无 BOM」标注 → 既有缺货消息 → 建档 BOM 指引 → 批量下达链路原样走通。本决策只解决「第一公里」，不碰生产联动语义（ADR-0004 不变）。

## Consequence

- CONTEXT.md「标准售价」词条中「销售对主数据无建档权」表述随之修订为「无人工建档/改档权；仅可通过建单内嵌快速建品创建新成品」。
- 出现第四种成品来源（销售自助）——物料仍只能人工建档，且快速建品端点强制 type=product，不会绕出物料记录。
- 恶意/误输名称即建档的成本仍在：靠「同名即选用」收敛重复，靠必填单位/售价保证记录可用；不再做更重的审批流（v1 取舍，售错可由基础资料端后续纠正）。
