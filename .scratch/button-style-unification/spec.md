# 全站操作栏按钮风格统一

Status: ready-for-agent

> 来源：2026-09-11 grilling 会话定案（8 题设计树全部确认）。基准 = 仓库管理员「商品资料管理」（物料管理）界面。

## Problem Statement

全站 23 个列表页的按钮风格各自为政：操作列按钮有实心、link、text 三种形式并存，有的带图标有的不带，有的页面（进货/销售系列）按钮纵向堆叠导致行高不一，有的缺 `size="small"`；工具栏有的缺图标，「新建退货单」颜色与其他新增按钮不同。用户在页面间切换时视觉跳跃明显，且纵向堆叠的操作列让同一列按钮在不同行不在同一水平线上。

## Solution

以「商品资料管理」（物料管理）页为基准，把全站所有列表页的**顶部工具栏**和**表格操作列**按钮统一为同一套规范：形式（link/实心）、大小、颜色语义、图标有无、排列顺序、换行行为全部一致；危险操作（删除/红冲/终止）保留红色警示；操作列固定宽度且按钮不换行，保证各行按钮在同一水平线、同一列对齐。

## User Stories

1. As a 仓库管理员, I want 所有页面的操作列按钮都是 link 文字小按钮, so that 界面风格与我熟悉的商品资料管理页一致
2. As a 仓库管理员, I want 操作列按钮在一行内水平平铺不换行, so that 每行按钮都在同一水平线上
3. As a 仓库管理员, I want 操作列宽度固定、跨行对齐, so that 扫描列表时视线不用左右跳动
4. As a 采购员, I want 进货管理/采购申请页的操作按钮从纵向堆叠改为水平平铺, so that 行高紧凑、一屏能看更多单据
5. As a 采购员, I want 采购申请页操作列按钮带 size="small", so that 与其他页面按钮大小一致
6. As a 销售员, I want 销售管理/销售退货页操作按钮风格与全站一致, so that 跨页面操作无割裂感
7. As a 系统管理员, I want 用户/部门/员工/公告/工作要求页的操作按钮从实心按钮改为 link 文字按钮, so that 与基准页一致
8. As a 系统管理员, I want 登录日志/操作日志/IP 策略页的 text 按钮改为 link 按钮, so that 形式统一
9. As any 角色, I want 「查看/详情」永远是蓝色（primary）, so that 我能凭颜色快速找到入口
10. As any 角色, I want 「编辑/修改」和流程确认类按钮是绿色（success）, so that 与基准页语义一致
11. As any 角色, I want 「作废/驳回/补料」是橙色（warning）, so that 我能感知这是警示性操作
12. As any 角色, I want 「删除/红冲/终止」保持红色（danger）且永远排在操作列最后, so that 危险操作有视觉警示且不易误触
13. As any 角色, I want 操作列按钮顺序统一为 查看→流程动作→编辑→警示类→危险类, so that 肌肉记忆可跨页复用
14. As any 角色, I want 操作列按钮不带图标, so that 与基准页一致且按钮更紧凑
15. As any 角色, I want 工具栏 查询=蓝+搜索图标 / 重置=默认+刷新图标 / 新增=绿+加号图标, so that 各页工具栏完全一致
16. As a 采购员/销售员, I want 「新建退货单」按钮是绿色（success）而非橙色, so that 新增类按钮颜色全站统一
17. As a 生产人员, I want 生产任务单下达弹窗的按钮改为「取消在左、确认在右」, so that 与全站对话框一致
18. As a 质检员, I want 质检页操作列按钮与其他页面一致, so that 风格统一
19. As a 开发者, I want 按钮规范沉淀为 ADR 和全局 CSS 工具样式, so that 未来新页面有章可循、不用逐页重复写不换行样式
20. As a 用户, I want 对话框内部表单辅助按钮、详情页、消息中心等非操作栏场景保持现状, so that 本次改动范围可控、不引入无关风险

## Implementation Decisions

### 基准规范（三类位置）

- **顶部工具栏**：实心按钮、默认大小（不写 size）、带图标。查询 `type="primary"`+Search 图标；重置 默认+Refresh 图标；新增类 `type="success"`+Plus 图标。
- **表格操作列**：`link` 文字按钮 + `size="small"` + 无图标 + 水平平铺，按钮间无分隔符（依赖全局间距样式）。
- **对话框底部**：取消在左（默认+Close 图标）、确认在右（`type="primary"`+Check 图标）。

### 颜色语义映射（全站唯一约定）

| 动作类别 | type |
|---|---|
| 查看 / 详情 | primary |
| 编辑 / 修改 | success（跟基准页） |
| 流程确认类（确认入库/出库、到货确认、审批通过） | success |
| 工具栏新增类 | success |
| 作废 / 驳回 / 补料（警示非毁灭） | warning |
| 删除 / 红冲 / 终止（不可逆危险） | danger |

### 操作列排列约定

- 顺序：查看/详情 → 流程动作（按业务流转顺序）→ 编辑/修改 → warning 类 → danger 类（永远置尾）。
- 不换行：操作列容器 `white-space: nowrap`；每页操作列设固定宽度，宽度按该页"单行同时可能出现的最多的按钮组合"计算，保证所有行按钮在同一水平线、列跨行对齐。

### 逐页修正清单（按菜单名）

| 修正项 | 页面 |
|---|---|
| 实心→link（去图标） | 供应商管理、用户管理、部门管理、员工管理、公告管理、工作要求 |
| 去图标（已是 link） | 进货管理、进货退货、销售管理、销售退货、生产入库、作废审批、部门审批、系统配置 |
| 纵向堆叠→水平平铺 | 进货管理、进货退货、销售管理、销售退货、生产入库 |
| 补 size="small" | 领料单、采购申请 |
| text→link（去图标） | IP 策略、登录日志、操作日志 |
| 混合风格统一（实心+link 混存） | 生产任务单、质检 |
| 工具栏补图标（查询/重置/新增） | 领料单、采购申请 |
| 「新建退货单」warning→success | 进货退货、销售退货 |
| 弹窗按钮顺序修正（取消左确认右） | 生产任务单 |
| 不动（基准本身） | 商品资料管理（物料/成品）、BOM 管理 |

库存预警为纯展示页无操作列，不涉及。

### 技术路线

- **逐页显式改属性**，不抽共享操作列组件：各页操作列按钮均按行状态条件渲染，逻辑差异大，抽组件收益低风险高，且不符合本仓库"每页自持"惯例。
- 全局样式表沉淀**一小段**操作列工具样式（不换行 + link 按钮间距），避免 22 页重复写 scoped style。
- 不引入 el-config-provider 全局默认（改动面不可控，且无法解决图标/布局差异）。
- 留档：新增 **ADR-0007** 记录本规范与语义色映射表（供未来新页面遵守）；progress.md 记会话日志。

## Testing Decisions

- **现状**：前端无测试框架（无 vitest/jest/playwright，scripts 仅 dev/build/preview），本spec 不引入测试框架。
- **测试接缝（唯一）**：`npm run build` 编译验证 + 浏览器人工目检。这是本仓库前端改动的既定先例（CLAUDE.md「验证习惯」：build 捕获编译错误 → dev 手测）。
- **好测试的标准**：本次是纯样式/模板属性改动，无逻辑行为变化，验证的是"渲染结果符合规范"而非实现细节；人工目检即外部行为验证。
- **目检覆盖**（用户执行）：至少抽查 3 个代表页——① 商品资料管理（基准页应保持不变）；② 采购申请（按钮最多的操作列，验证不换行/列宽）；③ 用户管理（实心→link 的代表）。建议另加进货管理（纵向→横向代表）。
- **自查清单**：实施者改完后输出逐页改动表（每页改了哪些属性），随同 build 结果一并交付。

## Out of Scope

- 对话框内部的表单辅助按钮（添加明细行、删除联系人、上传图片等）
- 详情页主操作按钮（工作要求详情页的接受/拒收等）
- 消息中心、布局头部（退出登录/菜单折叠）、首页快捷卡片、登录/注册/403 页
- 库存预警页（无操作列）
- 任何后端改动、任何业务逻辑改动
- 引入前端测试框架
- 抽取共享操作列/工具栏组件

## Further Notes

- 本规范定案过程：grilling 8 题（范围/属性/危险色/语义映射/图标与顺序/实现方式/边界/验收），用户全部按推荐确认，并补充"操作列按钮保持同一水平线、同一列"的硬性要求。
- 「编辑=success（绿色）」是基准页现状，用户已明确知悉并确认跟随基准。
- 操作列宽度需实施时逐页核对各状态按钮的条件渲染组合，取最宽组合定宽；若某页按钮组合过宽，优先保证不换行，再与用户确认是否缩文案。
