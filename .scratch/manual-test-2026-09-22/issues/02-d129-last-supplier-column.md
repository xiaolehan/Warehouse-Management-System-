# 02 · D129 采购申请全链「上次供应商」列

Type: task
Status: ready-for-human
Blocked by: 04（D131 行级供应商落地后口径自动正确——两票同批实现）

用户定案（2026-09-22 grilling，第三轮手测问题 2）：采购申请模块内**所有物料行**显示只读「上次供应商」列，口径与商品资料页「最新供应商」完全一致（D123 口径，D131 落地后为行级回退链）；目的——生产/仓储建单写备注前就知道该找谁，采购认领/定价时有参考。

## 范围

### 后端
- 新增轻量批量端点 `GET /base/goods/latest-suppliers?ids=1,2,3`：入参 goodsIds，返回 `{goodsId: {supplierId, supplierName, isDefault}}`（isDefault=true=无进货记录回退绑定供应商）。内核复用 `GoodsService.fillLatestSuppliers`（D131 后的行级口径），一次窗口查询防 N+1。
- 权限：可读物料的所有部门成员（warehouse/purchase/production/sales admin+employee）+ 超管均可调——供应商名非价格类敏感数据（区别于 D102 进价守卫）。
- **不改** options 接口、不改采购申请 VO（前端统一调批量端点，一处口径）。

### 前端（PurchaseRequestView.vue 为主，五处 + 生产补料一处）
统一封装一个小的行级展示（列：供应商名 + 无记录时灰色「默认」tag，复用 GoodsView 最新供应商列的展示范式）：
1. 手动建单弹窗明细行（PurchaseRequestView.vue:128-161 区）——选中物料后行内显示。
2. 缺货识别建单弹窗行（:96-126 区）。
3. 采购申请详情明细行（:257-276 区，按 D120 批次组内每行）。
4. 采购认领/修改到货计划弹窗行（:344-360 区，D109 格式说明旁——写备注时直接参考）。
5. 到货提交弹窗行（:287-314 区）。
6. 生产端补料弹窗「已有物料缺口」行（ProductionOrderView 内，生产写补料备注参考）。

各弹窗打开时按当前行 goodsIds 批量调一次端点；行增删后增量补查（简单做法：每次打开/行变化全量重查，弹窗行数有限）。

### 测试
- 单测：批量端点口径（有进货记录→行级供应商；无→绑定+isDefault=true；成品入参→空/忽略）；权限负测。
- 前端 build；E2E 断言端点返回。

## 验收
- 采购申请详情每行能看到该物料上次采购供应商；从没采购过的物料显示绑定供应商+「默认」标；六处入口口径一致。
